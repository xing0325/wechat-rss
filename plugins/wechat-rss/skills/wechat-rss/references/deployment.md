# 部署和维护

## 在目标机接手

1. 在本机 Windows 打开 Codex 桌面版，启用 Computer Use，手动登录微信。首次访问按界面授予应用权限。用 `node --version` 确认 Node.js 24+，用 `node -e "require('node:sqlite')"` 确认 SQLite 模块。
2. 在固定本地项目目录运行技能内的 `scripts/bootstrap.mjs <项目绝对路径>`，再在该项目里新开本机聊天。默认目录是 `%USERPROFILE%\wechat-rss`。如果已有项目，检查 CLI、配置与现有状态的版本和路径。初始化只补齐缺失文件。
3. 用 `node ./wechat-rss.mjs plan` 核对八个已配置来源、香港时区、20:30 与 23:30 及本机投递配置。首次安装的目标是「文件传输助手」，用于预演。按用户明确给出的会话全名填写 `delivery.chatName`，发送开关此时仍关闭。用 `status` 查看是否迁移了现有基线和待核对回执。先只读定位微信主窗口、文件传输助手和用户指定的正式会话，核对准确会话标题。
4. 启用正式发送前，按用户授权向文件传输助手发一次标明「预演」的结构化测试。查看 [预演](delivery.md#预演)。用一项临时本机定时任务验证触发后的同一 Codex 账号能读取项目和用 Computer Use 看到微信。试跑只读，完成后暂停或删除临时任务。
5. 手动验收和定时试跑通过后，按用户授权接管正式投递。若这两个微信来源相同且原机器也向同一群推送，先确认原机器的投递任务已停，确保只剩一个发送端。需要保留原队列时，先停旧机器的巡检和投递，处理待核对回执，复制 `state/wechat-rss.sqlite` 和可选的 `subscriptions.json` 到新项目相同位置，再跑目标机任务。保持目标机的 `config.json` 发送关闭直到交接完成。未迁移历史时按巡检说明建立基线，并确认群里当天同标题的消息是否已发送。
6. 交接条件满足后，在目标账号的本机项目创建或核对下列两个定时任务。优先更新同名同项目任务，保持每种任务只有一个。检查投递配置为 `mode: "native"`、`chatName` 与用户指定的正式会话全名相符，再将 `enabled` 改为 `true`。若现场验收或交接受阻，告知具体状态，保留发送开关关闭。

## 正式调度

使用 Codex 桌面版的本机定时任务。把同一个项目的绝对路径和下面的任务正文一起保存到两个任务，通过可用的自动化工具或应用界面创建。在任务正文引用「微信订阅推送」插件；若当前入口无法引用，则写明对应的本机技能文件绝对路径。先确认定时界面采用的时区。以下时间均为香港时间，界面使用其它时区时换算并校验下一次触发。目标机保持在线、交互式 Windows 桌面解锁、Codex 和微信可用。定时运行必须能使用 Computer Use。微信窗口可在后台，由 Computer Use 恢复到前台。

| 定时任务 | 香港时间 | 任务正文 |
| --- | --- | --- |
| 微信订阅 · 每日巡检 | 每天 19:50、22:50 | 在本机固定项目目录执行微信订阅插件的巡检流程。用项目的 SQLite，按香港时间准备此次触发对应的 20:30 或 23:30 汇总。按配置巡检所有来源，优先必看号，记录未覆盖原因，视频核验后暂停。预留前台给到点投递，不发送群消息。 |
| 微信订阅 · 每日群推送 | 每天 20:30、23:30 | 在同一本机固定项目目录执行微信订阅插件的投递流程。按香港时间取此次触发对应轮次，到点用已有入库内容出稿。只发送到用户已在本机配置且启用的原生微信正式会话。先查回执和群内同标题记录，确认发出后写回执。遇到未完成投递，报告确切原因。 |

19:50 与 22:50 启动后，如有时间在约 20:25 与 23:25 快速复查重点来源，并刷新尚未到点的待发稿。这是巡检任务的最后一步。到点有投递任务要用微信时结束巡检。

## 健康和换机检查

- 用 `plan` 查时区、配置、各来源最近巡检，用 `status` 查扫描覆盖、待发和未确认投递。用 `digest --round <HH:mm>` 查当天某轮稿件及 `sentAt`。状态为 `sending` 时先查真实群聊。
- 核对两个任务启用状态、下一触发、最近实际运行及本机交互桌面可用性。只凭任务已创建无法确认投递成功。第一次正式触发后，用群内消息和 SQLite 回执共同验收。
- 将 `subscriptions.html` 在浏览器打开可勾选额外公众号；导出 `subscriptions.json` 放在项目根。已有默认来源无需重复导入。给新增且身份不同的来源分配新 ID。首次输出应如实区分建立基线、未更新和巡检不完整。
- 迁移数据库只通过用户控制的文件传输。它包含微信链接、订阅记录及投递历史。插件本身带配置模板、工作流和运行脚本。
