# 投递

## 到点发送

1. 在项目根目录运行 `node ./wechat-rss.mjs plan`。按此次触发对应的轮次及香港当天日期操作。20:30 起至 23:00 前处理当天首轮，23:30 起至香港当天结束处理晚轮。提前启动时等到对应时间。越过对应时段时记录实际情况。跨日补发须有明确授权。
2. 用 `node ./wechat-rss.mjs digest --round <HH:mm>` 查该轮。已记录 `sent` 就结束。若无稿，到点即用 `prepare --round <HH:mm>` 根据已入库条目出稿。若为 `sending` 先按下方「回执核对」操作。
3. 确认 `delivery.enabled` 已打开，路由为 `native` 且 `chatName` 和用户明确授权的正式微信会话全名一致。默认的「文件传输助手」用于预演，正式发送前须改为用户指定的实际群聊或私聊。用 Computer Use 激活已登录的微信主窗口，核对群聊完整名称，允许会话标题尾部带成员数。检查发送框为空，并查看群记录是否已有该日期同标题的消息。若群内已发消息与待发稿完整一致，只领取并补登记成功回执。发现同标题但内容有差异，保留待发稿并报告，避免重复投递。其它路由只有在用户明确要求变更后才使用。
4. 用 `node ./wechat-rss.mjs claim-digest --round <HH:mm>` 取得 `attempt`、`route` 与完整 `message`。再次确认 `route`、会话和空白发送框后，将原样文本粘贴为一条多行微信消息。核对标题和末尾；使用当前界面的发送按钮只点一次。确认目标群出现同标题、内容相符的出站气泡，才写入成功回执。
5. 运行 `node ./wechat-rss.mjs finish-digest --attempt <ID> --result sent --note "<可核对证据>"`，再读该轮 `digest` 确认 `sent`。遇到短暂 UI 故障，短时恢复窗口并重核消息。结果不明时保留记录。说明确切卡点。

首轮消息标题为 `YYYYMMDD-8点半推送`。每条列标题、作者、微信链接。必看号为颖姐财经、股海牧羊人。其公众号或视频号任一有条目，即视为该账号这一轮有可发更新。没有条目时逐号显示未更新、巡检未完成、基线或链接待确认等真实状态。

晚轮标题为 `YYYYMMDD-晚间11点半推送`。上半段是新增，下半段是当日八点半的条目与状态。即使无新增也照常出稿。如果首轮没有生成，晚轮会注明缺少首轮记录。

## 回执核对

- `node ./wechat-rss.mjs status` 会列出投递中尚待确认的尝试。以对应的目标群和日期、消息标题及内容核对。发现同一条消息已经发出时，用该尝试的 ID 标记 `sent`。
- 确认没有发出时，使用原尝试 ID 执行 `finish-digest --attempt <ID> --result unsent --note "<可核对证据>"`，可再领取。点击后仍无法证实发送或未发送时，保持 `sending` 并报告待核对。
- 跨日补发已有的晚轮，给对应的 `digest`、`prepare` 与 `claim-digest` 加 `--day YYYYMMDD --round 23:30`。先核对该日群记录。补查内容已入库且待发内容均属于本次补发时，才用 `prepare --refresh` 更新这份已有稿件。

## 预演

按用户授权核对「文件传输助手」会话，发一条标题含「预演」的多行消息。可以用已确认的旧公众号或视频号链接测试在微信内打开。希望预演全部情况时，可以在同条消息放首轮状态、次轮新增、首轮回顾、无新增、未更新和待确认的示例。示例须标清，不创建正式出稿或写实际送达回执。不确定链接时用清楚的占位符，或由用户提供经过验证的微信链接。

## ClawBot 选配

现有脚本支持 `mode: "clawbot"`、`target: "<用户ID>@im.wechat"`、`accountId: "<Bot账号>"` 的私聊路由。若用户明确切换，先由收件人向官方微信插件发消息并验收会话。消息体可作为独立进程参数传给 `openclaw message send --channel openclaw-weixin --account <accountId> --target <target> --message <message> --json`。核实机器人返回和实际接收，完成回执。长时间无入站消息的行为应在目标机跨时段验收。
